Signed CDP leases v1

Accepted product and owner experience · wire schema · signed exchanges and rejection cases · scope and mediation cases

This is a conformance contract, not a broker. A transport without the following prerequisites must report lease support unavailable. Nothing here registers a handler, sends signaling, discovers a browser or opts an existing link into leases.

Transport and records

Provision a dedicated job-only Seven tray/registry at trusted construction. The existing slicc-link/1 signaling runtime is not a security discriminator. The owner selects the paired route and verifies device identity out of band; the adapter checks the actual broker DTLS certificate against its pre-paired pin. The selected end-to-end encrypted link and the job are bound in trusted state. Fail closed on pin mismatch, reconnect without verification, ordinary/mixed tray or unknown peer. Both peers' slicc.link.v1 HELLO caps must be exactly ["cdp-lease-v1"]. Do not advertise or register general host services, browser lists, generic CDP, routes, mounts or a full-trust seat. No JWT/key lookup or grant delivery through the signaling hub. The job opens all streams.

Link OPEN and OPENED payloads are each one unprefixed UTF-8 JSON object. Every subsequent record in the stream's DATA bytes is uint32be(length) || UTF8(JSON object), with 1 <= length <= 65536. Parse across fragmentation/coalescing; cap before allocation, reject truncated records, invalid UTF-8/BOM, duplicate member names (also after unescaping), unknown fields/types and out-of-state records. Numbers used as IDs/times are positive safe integers. Strings used as IDs/handles/refs are 1–128 ASCII letters, digits, _ or -. Base64url is always canonical RFC 4648 URL alphabet, unpadded, with zero unused bits; require decoded lengths. lease-v1.schema.json validates decoded shapes; it cannot replace byte-level checks, sequencing, trusted context or local policy. Tighter local limits may explicitly refuse, never truncate/widen a request.

Stage Job → broker Broker → job
Initial request OPEN {kind:"cdp-lease-v1",mode:"request",jwk,allow,ttlSeconds,reason?} OPENED {nonce}
Expansion request OPEN {kind:"cdp-lease-v1",mode:"request",jwk,allow,parent,reason?} OPENED {nonce}
Request proof {type:"proof",sig} {type:"pending",request}
Local decision No approval message exists in this direction {type:"grant",request,jwt} or {type:"error",reason,message}, then END
Data OPEN {kind:"cdp-lease-v1",mode:"data",jwk,jwt} OPENED {nonce}
Data proof {type:"proof",sig} {type:"ready"}
Action {type:"action",id,op,args} {type:"result",id,result} or {type:"error",id,reason,message}

Table notation names fields, not a second encoding. Literal JSON and complete framed examples are in the vectors. No per-action handle, JWT, target ID, CDP method or signature. On each data stream serialize actions, one in flight, strictly increasing positive IDs. Match response type, ID and result shape to the pending action. Snapshot yields {text:string}; successful goto/click/fill yield {}. Fail safely on a lost response, never implicitly reissue an action. Record errors and pre-accept RESETs must be safe, bounded and not echo peer/browser payloads, tokens, secrets, private URLs or response bodies. On terminal auth/expiry/revoke/protocol errors, close the stream. A scope miss need not terminate the original lease.

Create immutable broker request IDs only after proving possession. Bind a request to the exact OPEN, proven holder, selected link, epoch, eligible browser and (for expansion) exact still-live parent. Correlate the final grant to the pending ID on the same private stream. Receipt of pending, matching a thumbprint or accepting OPENED never grants browser access. Do not choose the first of multiple matches. Disconnection invalidates pending delivery; there is no anonymous retrieval by ID/JKT. Approval for a dead request cannot install a grant. Match, approve, sign and activate under broker-controlled state; compensate/retire undelivered grants if delivery fails.

JWT and holder proof

Compact JWS: exactly three segments. Ed25519 (RFC 9864), protected header exactly {"typ":"slicc-cdp-lease+jwt","alg":"Ed25519"}. Verify the 64-byte signature on ASCII of the original header.payload, never reserialize to verify. In production use a JOSE implementation supporting this exact algorithm and configure the local issuer key; ignore no critical fields, reject duplicate names and key URLs/embedded keys rather than trying another algorithm or fetching keys. The broker never gives this JWT to the browser. It is signed, not encrypted; do not include credentials in scopes or log it, pass it on a command line, put it in a URL, or expose it in the owner UI.

The only claims in v1 are iss, aud, jti, exp, cnf:{jkt}, browser_session, allow. Enforce exact configured issuer and audience strings, local active random grant ID, immutable grant state, current browser-session epoch and now < exp in Unix seconds. Do not derive authority from untrusted identifiers. aud identifies the broker's lease endpoint, not a website/job. browser_session is an epoch, not a profile name. Treat malformed or unsupported entries anywhere in allow as failure of the entire grant.

Both OPEN modes present exactly the public JWK {kty:"OKP",crv:"Ed25519",x}. Check 32-byte x. Its RFC 7638 SHA-256 thumbprint preimage is these UTF-8 bytes, no newline/whitespace: 

{"crv":"Ed25519","kty":"OKP","x":"<unpadded public x>"}

Use a fresh cryptographically random 32-byte nonce for every OPEN. Store its short exclusive deadline (no later than issuance + 30s) with the actual link, stream and immutable validated OPEN. nonce on the wire is unpadded base64url. The holder signature is pure Ed25519 over the following concatenation, not Ed25519ph, JSON, hex, the base64 nonce or an already-hashed message: 

ASCII("slicc-cdp-lease-v1:" + mode) || byte(0) || raw_nonce_32 || binding_32
request: binding_32 = SHA256(RFC7638 preimage above)
data:    binding_32 = SHA256(ASCII(exact compact JWT))

On a proof record, consume that stream's outstanding challenge on the first attempt even if verification fails. Verify with the key from OPEN; never accept a peer-supplied replacement nonce, stream ID or key at proof time. On data OPEN and again before ready, check the grant including cnf.jkt == base64url(request binding_32) for the presented key, live ID/epoch/time and local paired route. Never allocate/adopt a tab before successful proof. Challenges, streams, grants and pending effects die on restart/epoch change. Every reconnect, even for the same JWT, needs fresh proof. Proof is not authorization for any given operation.

Fixture context.now is a test clock. jwtCases override the named members of the base context, holder JWK or JWT (all other inputs unchanged). Some deliberately invalid JWTs are correctly signed. proofCases start from the indicated requestStream or dataStream; overrides change broker state, inputs or submitted proof. A consumed nonce is never restored. framingCases supply raw stream bytes in hex, chunk boundaries and expected decoded records (null = reject). lifecycleCases start with L1 live, its data channel authenticated and an L1 outcome pending release; live, data and result are the expected live grant, bound data channel and whether that old result reached the job. atExp advances the clock exactly to the deadline, including for idle channels. Only public keys are in the distributed JSON; the generator deliberately derives predictable fixture-only keys. Never trust these as installation keys. Header member order is not semantically significant. Equality of the compact JWT bytes is significant for the data proof.

Driver scope

Wire rules are typed {kind,url}. Use WHATWG HTTPS URL parsing and serialization. Reject credentials (even empty userinfo), controls, whitespace, backslashes, malformed percent escapes and wildcard authority. Wire rules must be canonical, without * glob syntax:

kind Stored url Comparison
origin serialized origin, no trailing slash equal scheme, ASCII host and effective port; all paths, queries and fragments
exact full canonical href, even / at the root serialized URLs equal, including the full query, fragment and empty delimiters
path-prefix origin + literal absolute path; no query/fragment or trailing slash except root same origin, and path equals the prefix or is a descendant at / boundary; ignore query/fragment

The --allow shorthand preserves the user's spelling before serialization: https://host is an origin, https://host/ an exact root, and any other path/query/fragment an exact URL. A trailing /** on a path with no query/fragment denotes a segment prefix (https://host/** is the root prefix). Reject ambiguous literal wildcard spellings, never widen. --add in the receipt flow denotes an explicit exact URL. See parseLeaseAllow and shorthandCases. A partial client may visibly refuse a shorthand or operation it cannot implement. This contract does not imply support for every type in every CLI.

Normalize browser document host case, IDNA and default port; do not infer sibling hosts or include subdomains. For narrow path rules decline ambiguous dot segments and percent-encoded slash/backslash in raw path. Use URL path segments, never string-prefix an entire URL or unescape it a second time. Deny protected browser/file/extension, catalog protected/credential origins and broker-specific protected surfaces first. Never turn a rule parse failure, unknown URL, opaque origin or inherited frame into an allowed origin. Implementations unable to match a canonicalized URL safely must refuse that action; do not silently convert a narrow rule into an origin. leaseScope(catalog, allow, extraProtectedOrigins?) returns null for an invalid rule set or a positive-scope predicate. A true is not a complete browser authorization.

At dispatch and result release check live grant, expiry, epoch, the same dedicated tab, same document/frame/URL generation and every ancestor URL on the target path. Sanitize snapshots to semantic results and omit unapproved subtrees. Invalidate stale refs on any intervening change, even a same-document navigation away and back. Verify the actual target at dispatch; refuse if focus, overlay or retargeting cannot be ruled out. No unrelated tabs, arbitrary coordinates, agent JS or raw network outputs. Vetted navigation/back to an approved URL may recover from an out-of-scope top page without reading that page or following its links. Lease scope governs driver operations, not site-authored JS, fetches, redirects, workers or dependencies. The browser can load a page without giving the driver access.

A denied expansion leaves the parent intact. On approval compare-and-replace the live parent atomically, keeping its holder, epoch, tab and absolute exp; mint a new random jti for the approved delta, retire old channels and challenge anew. If expired, revoked, replaced or disconnected in the meantime, reject the stale request. No time extension on a v1 delta. Close authenticated streams at expiry or revoke, even when idle; withhold pending results. No automatic renewal, replay, or adoption of another tab.

Kernel and native owner seams

The kernel exposes only a trusted boot-time, job-isolated lease facade (cdpLease:{tag,adapter}, CDP_LEASE_VERSION=1). Bind the dedicated job kernel to the authenticated host stamp; use kernel-internal SLICC_CDP_LEASE_URL only. Do not expose raw SLICC_CDP_URL. Neither a runtime query, hostname, public loopback port nor an opaque handle authenticates a job. No discovery, alternate-host routing or raw fallback. Slicc.leaseRequest params: initial {allow,ttlSeconds,reason?} or expansion {lease,allow,reason?} with delta only; returns {request,lease,jkt,reviewCommand?} (no JWT). Generate review text locally from a fixed template after validating the bare full jkt and exact typed rules; never print arbitrary remote shell text. If an offer cannot be expressed without losing rule types, refuse rather than widening it. Slicc.leaseAction params {lease,op,args}; goto:{url}, snapshot:{}, click:{ref}, fill:{ref,value}. Returns {result:...}. Errors use CDP error.data.reason, e.g. E_PENDING, E_SCOPE, E_EXPIRED, E_REVOKED, E_UNSUPPORTED, and safe human text. Native adapters need a job-private authenticated endpoint; a shared sandbox's public localhost is not one.

The owner GUI/TUI uses the authenticated local CLI control channel only, with build and process opt-in, a verified owned peer and live status.offers exactly ["cdp-lease-v1"]. cdp-lease-list yields {v:1,ok:true,pending,active}. Pending rows are {request,jkt,browser,link,allow,ttlSeconds} for initial and {request,jkt,browser,link,allow,parent} for expansions. Display unchanged deadline from the still-active parent entry, never restart the TTL. Initial TTL starts at local approval, not request creation. Use bare base64url JKT in the socket projection; only the CLI prepends jkt:. Active rows are {lease,jkt,browser,link,allow,exp}. Use {v:1,op,request} for cdp-lease-approve/cdp-lease-deny and {v:1,op:"cdp-lease-revoke",lease} for revocation; acknowledge {v:1,ok:true} then reload the authoritative snapshot. Same-process request IDs bind the exact key, link, browser, scope, parent and epoch. Consume once; never grant from stale snapshots or a missing parent. These are local broker IDs, not the remote job's handles. No grant token, private key or tray secret crosses the UI channel.

Running and consuming the contract

  • JS: import ./lease-v1.json, ./lease-scope-v1.json, ./schema/lease-v1.schema.json or ./lease-scope.mjs under @ai-ecoverse/slicc-browsers. npm run validate exercises wire, proof and scope cases. node --test test/integration/lease-{v1,page}.test.mjs also tests the real local page in a disposable Chromium profile. Set CHROME_PATH to Chrome for Testing and SLICC_HEADLESS=1.
  • Go: LeaseV1JSON(), LeaseScopeV1JSON() and LeaseV1SchemaJSON() return independent byte slices. Rust: LEASE_V1_SCHEMA, and with corpus, LEASE_V1 and LEASE_SCOPE_V1; no new runtime dependencies.
  • For broker integration: run node test/integration/fixtures/lease-page.mjs in the checkout. It binds loopback on an ephemeral port, generates a disposable TLS key/cert, and prints the host mapping, SPKI and synthetic owner sign-in path. Use only a new temporary profile with the printed flags, --no-proxy-server and --use-mock-keychain; never use real cookies or a logged-in profile. Stop with Ctrl-C. The default synthetic session is SameSite=Strict; pass {sameSite:"Strict"} explicitly in containment tests and assert leaseFixtureCookiePolicy on the owner-only harness returns {sameSite:"Strict",secure:true,httpOnly:true}. This helper discards values. A separate SameSite=Lax premise permits a human cross-site SSO link return; it is not evidence for the Strict case. The one-glyph square WOFF is original synthetic fixture data. The page renders a signed-in invoice with a cross-origin script, stylesheet, font, fetch, WebSocket, SPA URL change, service worker, cross-site iframe, receipt link, real form and a local human SSO handoff (sites.support/sso) back to the same tab. See premise test.

Conformance of static bytes and of an ordinary page in Chrome does not prove any consumer contains a real browser. End-to-end pairing, holder authentication, broker state, mediated actions and revocation remain release gates in the consuming repositories.
