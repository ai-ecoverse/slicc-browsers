Accepted product design · v1

One tab, one hour

“Let Ledger use my signed-in billing site until 11:00.” The owner chooses where the agent can work and when it must stop. They don’t have to know how the site is built.

Scope the driver, not the page loader. A CDN serving JavaScript is not another site the agent is asking to operate. An embedded support widget isn’t either—until the agent wants to read or click inside it.

What works with one approval?

Suppose you approve https://billing.example in a new tab of your Work profile.

Load the dashboard

The site runs its JS, loads fonts and scripts from its CDN, fetches invoices from an API and updates over a WebSocket. No extra lease requests. The agent sees the rendered invoice, not the API response or network log.

Use the application

Filter the table, open invoice 1042, type into a field, submit a form. History changes, query parameters and hash routes on that origin work by default. These are real actions as the signed-in user, not read-only access.

Encounter an embed

A chat iframe can render. Its presence doesn’t block the invoice. The agent gets a placeholder instead of that frame’s contents. Reading or clicking inside the widget requires its origin to be approved too.

Cross to another site

“View receipt” opens https://receipts.example. The agent stops at the boundary; the original tab stays usable. Add just the receipt URL, let the owner handle it, or skip it. No automatic prompt for ads, hidden frames or passive loads.

What this does not promise: URL scope is not a network firewall or a restriction on what the account can do. An approved app can show third-party data in its own UI, contact other services, or send an email when the agent clicks Send. Trust the app and its scripts as you would when using it yourself.

Agent: “Copy this line into your local terminal.”

The job adapter creates a key pair, keeps the private key in the sandbox, and computes the public key’s thumbprint. It registers a pending request under that thumbprint with its own Seven client. The agent sends this line in the task conversation: 

slicc lease review --to jkt:GcQ_AwlsJJaOnKknp1hXLIo08um7bX0k796qClT9C8s --allow https://billing.example --for 1h

Owner: paste, inspect, then decide

Holder     jkt:GcQ_AwlsJJaOnKknp1hXLIo08um7bX0k796qClT9C8s
Return via Ledger workspace · connected Seven tray
Browser    Chrome / Work · one new tab
Site       https://billing.example · 1 hour
Can read, click, type and submit as you.
[D]eny   [A]pprove until 11:00   [E]dit scope

review never grants on paste or on Enter alone. Select the browser and return link locally; narrow the site or duration if needed. On approval, the local broker binds cnf.jkt to the full supplied thumbprint and returns the JWT to the waiting adapter over the selected lease-only link. Denial issues nothing. No key file to download, second shell, or grant file to send back.

Where do the key and return link come from?

A thumbprint identifies a key; it is not an address or proof that the requester is named Ledger. Nothing is looked up on the internet. The owner trusts the source of the pasted line (their task conversation); the job presents its actual public JWK over the link. The broker recomputes its RFC 7638 thumbprint and requires proof of the matching private key before allowing browser use. Changing the key requires a new approval.

The CLI matches the pending request by full thumbprint on the owner-selected link. If there’s no link, say “In the requester’s Seven, choose Network → Link a device. Paste its join URL here.” Read the join secret with hidden input, not as part of the copyable command. The local broker starts or reuses a background lease-only peer and follows the tray. On first pairing the owner and job compare the broker’s device fingerprint through their task conversation. The tray hub signals WebRTC; it is not a key directory or JWT mailbox. If multiple links match, ask the owner to pick; if no matching job or supported transport is available, stop without issuing.

The adapter generates the line from a fixed command template, a base64url thumbprint and validated, shell-quoted scope arguments. Never interpolate free-text reasons into shell syntax. Only paste the expected review command from your own job, not an arbitrary shell snippet.

No-TTY automation: same thumbprint, explicit owner policy

An owner-controlled script issues directly on a known, paired route. It takes the requester’s thumbprint as data and supplies its own permitted scope and time. It does not execute an agent-supplied command or auto-confirm a review. 

owner$ slicc lease grant --to jkt:GcQ_AwlsJJaOnKknp1hXLIo08um7bX0k796qClT9C8s \
         --browser work --link ledger-tray --allow https://billing.example --for 1h --no-input

Missing or ambiguous browser, link or waiting holder: fail without issuing.

The authenticated adapter receives the replacement on its control stream; it updates the grant handle and opens a new data connection with proof for L2 before the job retries. Owner-side automation can make the same exact-match decision. Neither the job nor a web page can approve its own request.

The boundary

Check who is acting, and where

App code runs normally

Use the existing signed-in profile. Leave page JavaScript, service workers, fetch, redirects and the normal browser security model intact. Don’t maintain a dependency allowlist or scan network traffic for lease violations. Existing protected-origin rules still apply.

The driver stays scoped

Expose navigation, scoped snapshots and element actions via the local broker. Don’t expose raw browser CDP, arbitrary agent-supplied JS, network interception, cookie/storage export, arbitrary coordinates, file transfers or other tabs. Page-authored JavaScript and agent-authored JavaScript are different permissions.

URL matching without breaking SPA routes

Default to an exact HTTPS origin (scheme, host and effective port). All paths, query strings and fragments on it are in scope. No implicit sibling origins or subdomains. For a narrower lease, offer exact URL (full canonical URL including query and fragment) or path prefix such as https://billing.example/invoices/** (segment boundary, query and fragment unrestricted). Show the rule type in approval; never silently widen an exact URL into an origin. Prefixes do not isolate hash routes that share a path. These rules control which UI the agent may drive, not which records the app may fetch.

Navigation, popups and frames: pause the action, not the entire site

Bind a lease to one broker-owned task tab. Don’t enumerate or adopt existing tabs, including matching ones. Resolve element references to the current document and frame; require the top document and each frame on the target path to match. Use scoped semantic snapshots and element-bound actions, not a page-wide screenshot or a blind click through an overlay. Omit an unapproved subtree; if the intended element can’t be verified, decline that action, not the whole page.

Decline explicit out-of-scope navigation before dispatch. If site JS, a redirect, a popup or a history change moves outside scope, the browser may load it; the agent cannot inspect or drive it. Invalidate old references and withhold pending results on a document or URL change. Offer a vetted return to a known allowed URL. Keep popups outside agent control by default; for an approved destination, navigate the task tab there instead. A human can complete SSO locally and resume when the verified task tab returns—no need to lease the identity provider. Browser, file, extension and existing protected surfaces stay off limits regardless of approval.

Scope errors include a stable code, lease ID, a safe explanation and how to request more. Show a destination only when already known to the agent (e.g. from an allowed link); review an unknown redirect locally without disclosing its query. An explicit expansion shows only added URLs and any time change. A denied expansion leaves the old lease intact. Don’t replay a click/submit: if the site already acted, say so or report an unknown outcome.

Protocol flows

Two ways to issue. One way to connect.

A JWT records the owner’s decision. The job still has to prove it holds the matching key before the broker opens a task tab.

Implementation · JWT contract v1

Sign the lease once, not every click.

The issuer is the local slicc-cli broker; the holder is the job adapter. Use a signed JWT (compact JWS), not a bearer token. No OAuth server, refresh token or per-action signature. The browser never receives the token.

What the broker signs

Decoded example for L1, not a usable credential. Lease and session IDs are abbreviated; the holder thumbprint matches the pasted command; exp is 11:00 UTC on the example day. 

{"typ":"slicc-cdp-lease+jwt","alg":"Ed25519"}
{
  "iss": "urn:slicc:broker:work-7",
  "aud": "urn:slicc:cdp-lease:work-7",
  "jti": "L1",
  "exp": 1795518000,
  "cnf": {"jkt": "GcQ_AwlsJJaOnKknp1hXLIo08um7bX0k796qClT9C8s"},
  "browser_session": "work-epoch-42",
  "allow": [{"kind":"origin", "url":"https://billing.example"}]
}

iss identifies the trusted issuer; aud identifies this broker’s lease endpoint, not the job or the website. jti is a unique random lease ID in production. exp is an exclusive deadline in Unix seconds. cnf.jkt is the base64url SHA-256 RFC 7638 thumbprint of the holder’s public JWK. browser_session is an opaque epoch, not a reusable browser name or port. allow contains typed origin, exact or path-prefix rules with the matching semantics above. The broker associates the active ID with exactly one task tab.

JWTs are signed, not encrypted. Transfer grants over a private channel (or in an owner-only file); never put a token in a URL, command argument, log or page. Include no cookies, credentials or sensitive query parameters in the grant.

  1. Validate the grant on OPEN. Use a JOSE library and the broker’s configured issuer key. Pin the protected type and fully specified Ed25519 algorithm (RFC 9864); reject unsigned tokens, unexpected algorithms, duplicate claims or malformed rules. Never fetch a verification key at a location supplied by the token. Verify the signature, exact issuer and audience, future expiry, current browser epoch and active lease ID.
  2. Authenticate the holder on that connection. Use an encrypted channel authenticated end to end to the broker. Check that the presented public JWK matches cnf.jkt. Challenge the holder to sign a short-lived unpredictable nonce and the digest of this compact JWT in a domain-separated lease-open message. The broker binds the nonce to this connection and JWT and consumes it once. A copied JWT or a proof replayed on a different connection cannot open a tab. Reconnects require fresh proof.
  3. Authorize each action. Cache verified claims on the authenticated connection, not a blanket “allowed” bit. Before dispatch and before returning results, check live ID, deadline, epoch, tab/document/frame and URL rule. Expiry or revocation removes authority and closes active streams even when idle. Browser or broker restart invalidates the epoch.
  4. Replace, don’t edit. Only after local approval, mint a JWT with a new jti, same holder and the approved rule delta. Activate it and retire the still-active parent atomically; close old data streams. Keep the original expiry unless the owner explicitly changes it. If the parent expired or was revoked first, require a fresh grant. Denial changes nothing. No automatic renewal or retry of site actions.
Delivery across the repositories
  • slicc-cli: own grants, background lifecycle, local approvals and a lease-only route beside the existing relay. Use its target/frame and protected-origin guard. Run trusted locator helpers here, not in the remote client. No legacy full-CDP or alternate host capability on the lease route.
  • slicc-cdp: map existing goto, snapshot, click and fill commands to the lease route. Unsupported operations say so rather than falling back to discovery. Native and WASI use the same errors.
  • slicc-browsers: share URL rule and guard fixtures. Keep the hard-deny catalog separate from positive user scope.
  • Sliccy: use the owned CLI’s authenticated local control channel for approve, inspect and revoke. A TUI uses the same model; an old CLI reports lease support unavailable.
  • slicc-kernel: SLICC maps its paired link to the lease task client. For Cloudflare, add the missing adapter hook, bind the holder key to the job in the Durable Object, and use a broker-authenticated outbound tunnel. Another sandbox can use the native adapter. Reuse existing trusted links where available; an internet-reachable raw debugging port is never a prerequisite.
Release gate: prove compatibility as well as containment

Run a signed-in SPA fixture with third-party JS/fonts, API calls, WebSocket updates, query/hash routing, a support iframe and a form submission. Pass: the job completes the in-scope task with one approval and zero dependency prompts. A cross-origin receipt needs exactly one explicit expansion. SSO handoff returns to the same lease. Measure unexpected refusals on representative consented workflows before rollout.

Start with an empty owner key directory: paste the request and confirm that no lease exists before approval. Test first pairing, no return link, a key mismatch, denial and delivery to the waiting job. Reject a tampered or unsigned JWT, wrong issuer/audience/epoch, mismatched holder, replayed proof or retired ID before CDP dispatch. Test the exact expiry boundary on an idle stream. Also test redirect and same-document races, stale element references, frame replacement/focus, overlays, popup handling, expiry during output and revoke on reconnect. Verify no outside content or action reaches the job, no unrelated tab is disclosed, and a blocked embed leaves the rest of the app usable. If an operation can’t be made safe, withhold that operation—not all JavaScript.

Scope of this proposal: mediated interaction with a trusted website, not read-only account delegation, browser-wide debugging or network isolation. Commands and mockups describe a design, not a released interface.
